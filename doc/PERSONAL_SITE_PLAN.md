## Мета і позиціонування

над чотирма окремими вертикалями, а розробка на замовлення лишається **активним джерелом доходу** у власному хабі.

## Незмінні принципи
1. **URL постів не переносимо.** Нові розділи — хаби поверх наявних URL. Один пост = один self-canonical,
   але може бути в кількох добірках. Якщо колись переносити — лише 1:1 через 301/308 з оновленням canonical,
   breadcrumbs, sitemap, RSS, внутрішніх посилань; ніколи не редиректити кілька статей на один хаб.
2. **Комерційні сторінки живуть** (`/services/*`, `/pricing/`, `/projects/*`, клієнтські статті) — у них SEO-капітал і дохід.
3. **Одна велика зміна за раз + вимірювання** проти baseline. Бренд/IA — окремо від міграції движка і від платежів.
4. **Паркінсон-контент — поза пейволом.** Рубрика = «досвід пацієнта», не медичний довідник (рецензента-невролога немає).
5. **Жодного прийому коштів до визначення легальної структури продавця** (див. Ф5).
6. Домен не міняємо (переїзд домену — найризиковіша SEO-операція; «parkinsandr» працює як авторський нік).

### Ф1 — Комерційний хаб `/services/` (головна ще НЕ змінюється)

**DoD:** усі комерційні CTA ведуть на `/services/`; головна без змін; 0 broken; ліди стабільні.

### Ф2 — Тематичні хаби (без переносу постів)

### Ф5 — Монетизація MVP — ⛔ ЗАБЛОКОВАНО
**Блокер:** юридична структура продавця ще не визначена (питання власника, поза репо).
Прийом коштів — лише на рахунок легального продавця, від імені якого оферта, чеки й privacy.
Технічна частина проєктується **незалежно від того, хто продавець** (merchant-токен — конфіг).
- `/support/` — «підтримка автора» (не «донат»: слово не робить платіж благодійним чи неоподатковуваним).
- `/shop/` — перший разовий продукт (збірка оповідань, аудіоверсія, трек/альбом, розширений лонгрід).
- Схема: `checkout API → mono hosted payment → підписаний webhook → entitlement у Supabase → лист з
  короткоживучим signed URL на приватний файл`.
- Вимоги безпеки: доступ лише після webhook або перевірки статусу інвойсу (НЕ `redirectUrl`); ідемпотентний
  webhook; звірка суми/валюти/reference; порядок подій; журнал платежів; процес повернень і chargeback.
- Статичний пейвол не захищає контент (прихований CSS/JS чи секретний URL лишають матеріал у браузері).
**DoD:** визначено легального продавця; оферта/повернення/ПРРО/privacy готові; перший продукт продається end-to-end.

### Ф6 — Міграція на Astro
- Після стабілізації IA (≥ 4–8 тижнів після Ф3). URL 1:1, еквівалентний HTML, schema без втрат.
- Спільні layout/меню/футер, пости в Markdown, автоматичні хаби/теги/фіди/sitemap.
- Унікальні сторінки (лонгрід velozaizd тощо) можна лишити як є. Next.js — надмірний.

### Ф7 — Членство (лише за доведеного попиту)
- Тригер: повторні покупки або передзамовлення.
- mono — нативні регулярні платежі (create/status/list/payments), свій планувальник не потрібен; на нашому боці —
  entitlements, невдалі списання, скасування. Retry-поведінку mono звірити при проєктуванні.
- ⚠️ Членство = регулярне зобов'язання автора — з урахуванням здоров'я це реальний ризик; перевага разовим продуктам.

## Паралельні треки (не блокують Ф0–Ф4)
- **Юридичний:** структура продавця, КВЕД, публічна оферта, повернення для цифрового контенту,
  ПРРО/фіскалізація (позиція бухгалтера — цифровий контент не звільнений автоматично), `/privacy/` (зараз під фізособу-блогера).
- **Права на контент:** ліцензії на Midjourney-ілюстрації, музику й кліпи (якщо з AI-інструментів — умови
  комерційного використання), фото й історії реальних людей — перевірити ДО продажу.
- **Паркінсон:** редакційна політика рубрики; свідоме рішення щодо медичних деталей у кожному пості
  (опубліковане практично не відкликати з пошуку, архівів і AI).
- **Email/DNS:** Resend + `send.parkinsandr.tech` (з плану підписки).
